# امنیت کلید API و سرور

## اگر کلید شما جایی منتشر شده است

هر `API Key` و `API Secret` که در اسکرین‌شات، چت، تیکت پشتیبانی یا مخزن گیت
دیده شود را **منقضی‌شده** بدانید. ترتیب اقدام:

1. در پنل صرافی به بخش «مدیریت API» بروید و کلید منتشرشده را **حذف/باطل** کنید.
2. کلید جدید بسازید با مجوزهای حداقلی: **Read + Trade** (بدون Withdrawal).
3. اگر برداشت برای آن کلید ممکن بود، تاریخچه‌ی برداشت‌ها و ورودها را بررسی کنید.
4. رمز حساب و 2FA را عوض کنید (احتمال لو رفتن رمز را هم در نظر بگیرید).
5. کلید جدید را فقط در `.env` روی سرور قرار دهید؛ در چت، ایمیل یا تصویر نه.

این ربات نه کلیدها را در دیتابیس ذخیره می‌کند و نه در لاگ چاپ می‌کند؛ لاگر یک
فیلتر حذف خودکار دارد که هر مقدار کلید را با `***REDACTED***` جایگزین می‌کند و
`check` فقط اثر انگشت SHA-256 کوتاه کلید را نشان می‌دهد تا بتوانید بدون دیدن خود
کلید مطمئن شوید کلید درست بارگذاری شده است.

## حداقل‌سازی مجوزها

| مجوز | لازم؟ | توضیح |
|---|---|---|
| Read | ✅ | قیمت، کندل، موجودی |
| Trade | ✅ | ثبت/لغو سفارش |
| Withdrawal | ❌ **هرگز** | ربات هیچ کدی برای برداشت ندارد |
| Futures/Margin | ❌ | این نسخه فقط اسپات |

اگر صرافی اجازه می‌دهد، محدودیت IP را روی IP سرور تنظیم کنید و کلید را با
انقضای زمانی بسازید.

## نگهداری کلید روی سرور

```bash
chmod 600 .env
chown trader:trader .env
```

- از root برای اجرای ربات استفاده نکنید (unit نمونه با کاربر `trader` اجرا می‌شود).
- سرور را به‌روز نگه دارید و ورود با رمز SSH را غیرفعال کنید (فقط کلید).
- فایروال: فقط SSH؛ ربات نیازی به پورت باز ندارد (خروجی HTTPS به صرافی/تلگرام).
- `state/` حاوی تاریخچه‌ی معاملات و موجودی است: `chmod 700 state`.

## سوئیچ توقف

دو راه مستقل:

```bash
python -m trader panic        # ساخت state/STOP با پیام فارسی
touch state/STOP              # معادل فایل
```

در هر چرخه، وجود این فایل باعث می‌شود ربات هیچ سفارشی ثبت نکند و در لاگ/تلگرام
هشدار دهد. `resume` فایل را برمی‌دارد.

## قفل اجرای هم‌زمان

`run` قبل از شروع، `state/trader.lock` را می‌سازد تا دو فرآیند روی یک حساب
سفارش نگذارند (ریسک اصلی: سفارش‌های تکراری). اگر ربات کرش کرد و قفل ماند، پس از
مطمئن شدن از نبودن فرآیند، فایل را پاک کنید.

## چیزهایی که این ربات از عمد ندارد

- برداشت خودکار یا «انتقال به کیف پول».
- ذخیره‌ی رمز پنل صرافی.
- اهرم (leverage) و معاملات فیوچرز.
- وب‌سرور عمومی/داشبورد اینترنتی که سطح حمله اضافه کند.
- استفاده از کلید در URL یا لاگ.
