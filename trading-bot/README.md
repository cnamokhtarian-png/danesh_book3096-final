# ربات معامله‌گر و مدیریت دارایی کریپتو (نوبیتکس / والکس)

یک ربات پایتونِ مستقل و قابل ممیزی که داده‌ی بازار را از صرافی ایرانی می‌گیرد،
با اندیکاتورهای تکنیکال تصمیم می‌گیرد، اندازه‌ی سفارش را با قواعد ریسک تعیین
می‌کند، سفارش **محدود (limit)** ثبت می‌کند و نتیجه را در تلگرام/لاگ گزارش می‌دهد.

> **تازه‌کار هستید؟** فقط [`docs/QUICKSTART-FA.md`](docs/QUICKSTART-FA.md) را بخوانید و
> `start.bat` (ویندوز) یا `bash start.sh` (مک/لینوکس) را اجرا کنید. یک دستیار فارسی
> همه‌چیز را با چند سؤال ساده تنظیم می‌کند. راهنمای کامل گام‌به‌گام: `setup_wizard.py`.

> **حالت پیش‌فرض «کاغذی» (paper) است.** تا زمانی که `TRADING_MODE=live` و عبارت
> تأیید `LIVE_TRADING_CONFIRM` را تنظیم نکنید، هیچ سفارش واقعی به صرافی نمی‌رود.
> ربات **هرگز** به API برداشت دسترسی ندارد و از آن استفاده نمی‌کند.

## ۱) معماری

```
[صرافی: نوبیتکس/والکس]
        │  فقط قیمت، کندل و موجودی (GET) + ثبت سفارش limit (POST)
        ▼
[کلاینت صرافی] ──► [اندیکاتورها: EMA / RSI / ATR / حجم]
        │                        │
        │                        ▼
        │            [تصمیم قاعده‌محور BUY/SELL/HOLD]
        │                        │
        │            [AI اختیاری: تأیید یا وتو]
        │                        │
        │            [لایه ریسک: اندازه، سقف، حد ضرر]
        ▼                        ▼
[ثبت سفارش + پیگیری پرشدن] ──► [گزارش تلگرام / لاگ / SQLite]
```

| لایه | فایل | کار |
|---|---|---|
| تنظیمات و نگهبان‌ها | `trader/config.py` | اعتبارسنجی `.env`، اجبار حالت ایمن، اثر انگشت کلید |
| کلاینت صرافی | `trader/broker/nobitex.py`، `wallex.py` | قیمت، کندل، موجودی، سفارش، لغو |
| شبیه‌ساز | `trader/broker/paper.py` | اجرای سفارش کاغذی با کارمزد و اسلیپیج |
| استراتژی | `trader/strategy/rules.py` | EMA/RSI/حجم/نوسان → BUY/SELL/HOLD |
| هوش مصنوعی | `trader/strategy/ai.py` | اختیاری؛ `veto` (پیش‌فرض) یا `independent` |
| ریسک | `trader/risk.py` | تعیین حجم، سقف موقعیت، ضرر روزانه، اسپرد، کول‌داون |
| هسته | `trader/engine.py` | چرخه، اجرا، حد ضرر/سود، پایداری وضعیت |
| گزارش | `trader/notify/telegram.py` | تلگرام + لاگ با حذف خودکار کلیدها |
| CLI | `trader/cli.py` | `check`، `once`، `run`، `status`، `report`، `panic` |

## ۲) راه‌اندازی سریع (۵ دقیقه)

```bash
cd trading-bot
python setup_wizard.py             # ← ساده‌ترین راه: چند سؤال فارسی و تمام

# یا به‌صورت دستی:
python3 -m venv .venv
source .venv/bin/activate          # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # سپس کلیدها را داخل .env بگذارید
chmod 600 .env

python -m trader check             # بررسی تنظیمات، اتصال، کندل، تلگرام
python -m trader once              # یک چرخه؛ در حالت paper معامله کاغذی می‌شود
python -m trader run               # اجرای مداوم (هر CYCLE_SECONDS)
```

اولین بار که می‌خواهید رفتار ربات را ببینید، همین حالا و بدون کلید/اینترنت:

```bash
python scripts/demo_offline.py     # خرید → جلوگیری از خرید دوم → خروج با حد ضرر
```

`check` هیچ سفارشی ثبت نمی‌کند. اگر خطای «اسپرد بازار» یا «داده‌ی کندل» دیدید،
جزئیات همان خط را بخوانید؛ پیام‌ها فارسی و قابل اقدام‌اند.

### دستورها

| دستور | کار |
|---|---|
| `python -m trader check` | پیش‌پرواز: تنظیمات، قیمت، کندل، موجودی، تلگرام |
| `python -m trader once` | یک چرخه‌ی کامل و خروج |
| `python -m trader run` | اجرای مداوم با قفل فایل (دو نمونه هم‌زمان اجرا نمی‌شوند) |
| `python -m trader run --dry-run-live` | اگر تنظیمات live بود، به‌اجبار کاغذی اجرا کن |
| `python -m trader status` | قیمت، نقدینگی، موقعیت، دارایی کل، سود/زیان امروز |
| `python -m trader report` | آخرین معاملات و تصمیم‌ها از دیتابیس محلی |
| `python -m trader panic` | ساخت سوئیچ توقف؛ چرخه‌ی بعدی هیچ سفارشی ثبت نمی‌شود |
| `python -m trader resume` | برداشتن سوئیچ توقف |
| `python -m trader reset-paper` | پاک کردن وضعیت حالت کاغذی (فقط paper) |
| `python setup_wizard.py` | دستیار فارسی ساخت `.env` (بدون دانش فنی) |
| `bash stop.sh` / `stop.bat` | توقف اضطراری با یک کلیک |

## ۳) اتصال به صرافی

### نوبیتکس

1. در پنل نوبیتکس → «تنظیمات» → «API» یک توکن بسازید.
2. مجوزها: **خواندن (Read) + معامله (Trade)**. **برداشت (Withdrawal) را خاموش بگذارید.**
3. توکن را در `.env` بگذارید: `NOBITEX_API_TOKEN=...`
4. نمادها: `BTCIRT`، `ETHIRT`، `BTCUSDT`، … (ریال در نوبیتکس به تومان نرمال می‌شود).

این ربات از این اندپوینت‌ها استفاده می‌کند:

| کار | اندپوینت |
|---|---|
| قیمت/اسپرد | `GET /v3/orderbook/{SYMBOL}` (و در صورت خطا `GET /market/stats`) |
| کندل | `GET /market/ohlc?symbol=…&resolution=5` |
| موجودی | `POST /users/wallets/list` |
| ثبت سفارش | `POST /market/orders/add` (limit) |
| وضعیت سفارش | `POST /market/orders/status` |
| لغو | `POST /market/orders/update-status` |

جزئیات و لینک مستندات: [`docs/API-NOTES.md`](docs/API-NOTES.md).

### والکس

1. در پنل والکس → «API» کلید بسازید (فقط معامله و مشاهده).
2. `EXCHANGE=wallex` و `WALLEX_API_KEY=...` (هدر `x-api-key`).
3. نمادها: `BTCUSDT`، `BTCIRT` و … .

## ۴) ربات چطور تصمیم می‌گیرد؟

هر چرخه (`CYCLE_SECONDS`، پیش‌فرض ۳۰۰ ثانیه):

1. **حد ضرر / حد سود موقعیت باز** بررسی می‌شود — اولویت مطلق بر هر سیگنال دیگری.
2. **قواعد تکنیکال** روی کندل‌ها:
   - خرید: قیمت بالای EMA سریع، EMA سریع بالای EMA میانی، قیمت بالای EMA بلندمدت،
     RSI در بازه‌ی `۴۵–۷۰` و حجم حداقل `۰.۵×` میانگین.
   - فروش: شکست EMA میانی، RSI ≥ ۷۸ (اشباع خرید) یا RSI < ۳۰.
   - صبر: بازار بدون روند، نوسان بسیار بالا (`ATR > ۶%`) یا داده‌ی ناکافی.
3. **هوش مصنوعی (اختیاری)**: در حالت `veto` فقط می‌تواند تصمیم را وتو کند
   (تصمیم را عوض نمی‌کند). در حالت `independent` خودش پیشنهاد می‌دهد، اما اندازه،
   سقف‌ها و حد ضرر همیشه از لایه‌ی ریسک می‌آیند.
4. **لایه‌ی ریسک** حجم را تعیین می‌کند.
5. سفارش **limit** در بهترین قیمت سمت مقابل ثبت و تا `ORDER_FILL_TIMEOUT` ثانیه
   پیگیری می‌شود؛ اگر پر نشد، **لغو** می‌شود (سفارش سرگردان نمی‌ماند).
6. گزارش در لاگ و تلگرام + ثبت در `state/trader.sqlite3`.

قواعد دقیق و نحوه‌ی تنظیم: [`docs/STRATEGY.md`](docs/STRATEGY.md).

## ۵) اقتصاد معامله (چرا «معامله‌ی زیاد» سود را می‌خورد)

با کارمزد ۰.۴٪ در هر طرف، هر خرید+فروش حدود ۰.۸٪ هزینه دارد:

| پروفایل | معاملات روز | حد سود / ضرر | سود خالص هر برد | حداقل نرخ برد لازم |
|---|---|---|---|---|
| محافظه‌کار | ۴ | ۵٪ / ۲.۵٪ | ۴.۲٪ | ≈۴۴٪ |
| متعادل | ۸ | ۴٪ / ۲٪ | ۳.۲٪ | ≈۴۷٪ |
| فعال | ۲۰ | ۲٪ / ۱.۲٪ | ۱.۲٪ | ≈۶۲٪ |

هر سه عدد را `python -m trader check` و `setup_wizard.py` نشان می‌دهند. پروفایل
«فعال» با پول واقعی توسط دستیار مسدود می‌شود.

## ۶) مدیریت ریسک (مقادیر پیش‌فرض)

| تنظیم | پیش‌فرض | معنا |
|---|---|---|
| `MAX_POSITION_PCT` | ۵٪ | سقف ارزش هر ورود نسبت به دارایی کل |
| `MAX_TOTAL_POSITION_PCT` | ۱۵٪ | سقف مجموع موقعیت باز |
| `MAX_DAILY_LOSS_PCT` | ۳٪ | پس از این افت، خرید جدید متوقف می‌شود (فروش/خروج آزاد است) |
| `MAX_TRADES_PER_DAY` | ۸ | سقف تعداد معاملات روز |
| `COOLDOWN_MINUTES` | ۳۰ | فاصله‌ی حداقلی بین دو معامله |
| `STOP_LOSS_PCT` / `TAKE_PROFIT_PCT` | ۲٪ / ۴٪ | حد ضرر و حد سود موقعیت |
| `MAX_SPREAD_PCT` | ۱.۵٪ | در بازار بی‌عمق/پراسپرد وارد نمی‌شود |
| `MAX_SLIPPAGE_PCT` | ۰.۵٪ | فاصله‌ی قیمت خرید از آخرین معامله |
| `MIN_TRADE_QUOTE` | خودکار | حداقل ارزش سفارش (تومان/دلار) |

خرید فقط یک موقعیت در هر زمان باز می‌کند (بدون هرم‌سازی). فروش، کل موقعیتِ
**مدیریت‌شده توسط ربات** را می‌بندد.

## ۷) فعال‌کردن معامله‌ی واقعی (فقط با آگاهی کامل)

```bash
# .env
TRADING_MODE=live
LIVE_TRADING_CONFIRM=I-UNDERSTAND-THE-RISK
NOBITEX_API_TOKEN=...
MAX_POSITION_PCT=1
STOP_LOSS_PCT=1.5
```

سپس:

```bash
python -m trader check      # همه‌ی موارد باید سبز باشند
python -m trader once       # یک چرخه‌ی کنترل‌شده
python -m trader run
```

چک‌لیست ایمنی:

- [ ] کلید API فقط `Read + Trade` دارد و **Withdrawal خاموش** است.
- [ ] در پنل صرافی برداشت به آدرس‌های تأییدشده/whitelist محدود شده است.
- [ ] 2FA حساب فعال است و کلید را در جایی امن نگه داشته‌اید.
- [ ] ابتدا چند روز در حالت `paper` اجرا شده و رفتار ربات را دیده‌اید.
- [ ] مبلغ اولیه‌ای که حاضرید از دست بدهید کوچک است.
- [ ] دستور `panic` را یک‌بار تمرین کرده‌اید.

> کلیدهایی که در تصویر چت/اسکرین‌شات دیده شده‌اند را **فوراً باطل (Revoke) و
> دوباره بسازید** — هر کلیدی که جایی منتشر شود، دیگر امن نیست.

## ۸) اجرای ۲۴ ساعته روی VPS

```bash
# روی سرور اوبونتو
sudo adduser --system --group trader
sudo mkdir -p /opt/danesh-trader && sudo chown -R trader:trader /opt/danesh-trader
# کد را در /opt/danesh-trader کپی کنید (کل پوشه‌ی trading-bot)
cd /opt/danesh-trader
sudo -u trader python3 -m venv .venv
sudo -u trader .venv/bin/pip install -r requirements.txt
sudo -u trader cp .env.example .env && sudo -u trader chmod 600 .env
# کلیدها را در .env بگذارید

sudo cp deploy/trader.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now trader
sudo journalctl -u trader -f
```

- وضعیت و لاگ در `/opt/danesh-trader/state` نوشته می‌شود (`ReadWritePaths` در unit).
- توقف اضطراری: `sudo -u trader .venv/bin/python -m trader panic` یا
  `touch /opt/danesh-trader/state/STOP`.
- برای تایم‌زون درست، `TIMEZONE` را تنظیم کنید (گزارش‌ها UTC ذخیره می‌شوند).

## ۹) عیب‌یابی

| نشانه | علت رایج | راه‌حل |
|---|---|---|
| `HTTP 401/403` | توکن اشتباه/منقضی یا مجوز Trade ندارد | کلید را بازسازی کنید؛ مجوز Read+Trade |
| «داده‌ی کندل کافی نیست» | `CANDLE_LOOKBACK` کم یا بازار تازه | `CANDLE_LOOKBACK=300` و `EMA_TREND` کوچک‌تر |
| «اسپرد بازار بیش از حد مجاز» | بازار بی‌عمق | صبر کنید یا `MAX_SPREAD_PCT` را واقع‌بینانه تنظیم کنید |
| «سفارش در مهلت مقرر پر نشد» | قیمت limit جابه‌جا شد | `ORDER_FILL_TIMEOUT` بیشتر یا اسپرد بهتر |
| «تأیید AI داده نشد» | مدل مطمئن نبود | `AI_MIN_CONFIDENCE` را کم کنید یا `LLM_ENABLED=false` |
| دو نمونه هم‌زمان | فایل `state/trader.lock` | نمونه‌ی قبلی را ببندید؛ اگر کرش کرده، فایل قفل را پاک کنید |
| گزارش تلگرام نمی‌آید | `TELEGRAM_CHAT_ID` اشتباه | به ربات پیام بدهید و `check` را اجرا کنید |

## ۱۱) محدودیت‌ها و هشدارها

- این ابزار **توصیه‌ی مالی نیست**. سود گذشته تضمین آینده نیست و بازار کریپتو
  می‌تواند در چند دقیقه بخش بزرگی از سرمایه را از بین ببرد.
- استراتژی روی کندل‌های تاریخی تست نشده (backtest ندارد)؛ پیش از پول واقعی،
  حالت کاغذی را جدی بگیرید.
- سفارش‌ها limit هستند تا هزینه‌ی لغزش کنترل شود؛ در بازارهای کم‌عمق ممکن است
  پر نشوند (که بهتر از پر شدن با قیمت بد است).
- معامله‌ی کریپتو در ایران تابع مقررات و مالیات است؛ مسئولیت آن با شماست.
- ربات فقط موقعیت‌هایی را می‌فروشد که خودش خریده باشد؛ دارایی از پیش موجود در
  حساب را دست نمی‌زند.
